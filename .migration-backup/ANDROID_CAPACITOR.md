# FocusArx Android APK with Capacitor

FocusArx stays a Next.js app. Capacitor wraps the existing app in an Android WebView, while Prisma, NextAuth, API routes, AI endpoints, dashboard analytics, and session persistence continue to run from the Next.js server.

## What Was Added

- `@capacitor/core`, `@capacitor/cli`, `@capacitor/android`
- Native plugins for splash screen, status bar, app lifecycle, keyboard, and local notifications
- `capacitor.config.ts` with app id `com.focusarx.app` and app name `FocusArx`
- `android/` native project generated by Capacitor
- Android permissions for camera, internet, network state, wake lock, foreground service, and notifications
- Android cleartext/network config for emulator and LAN development
- Native status bar, splash screen, keyboard resize, and keep-awake setup
- Mobile viewport and safe-area CSS

## Important Architecture Note

This app uses Prisma and Next.js API routes. Those cannot run inside an Android WebView. The APK must connect to a running FocusArx Next.js server:

- Local emulator: use `http://10.0.2.2:3000`
- Physical device on same Wi-Fi: use `http://YOUR_COMPUTER_LAN_IP:3000`
- Production APK: use your deployed HTTPS domain

Camera access in Android WebView requires the page origin to be secure or app-trusted. Capacitor's native WebView plus the Android `CAMERA` permission allows `navigator.mediaDevices.getUserMedia` to work when the app loads through Capacitor.

## Terminal Commands

Run all commands from:

```powershell
cd E:\FocusArx\focusarx
```

Install dependencies:

```powershell
npm install
```

This installs all package dependencies from `package-lock.json`, including Capacitor and the existing Next.js/Prisma stack.

Generate Prisma client and start the Next.js server for emulator testing:

```powershell
npm run dev
```

This runs `prisma generate` and then starts `next dev` on port `3000`.

Sync Android for the emulator:

```powershell
$env:CAPACITOR_SERVER_URL="http://10.0.2.2:3000"; npm run cap:sync
```

This prepares Capacitor's required `out/` folder, writes native Capacitor config, copies web assets, and updates Android plugins. `10.0.2.2` is the Android emulator's address for the host machine.

Run on an Android emulator:

```powershell
$env:CAPACITOR_SERVER_URL="http://10.0.2.2:3000"; npm run android:run
```

This syncs Capacitor and launches the app on a connected emulator/device.

Open Android Studio:

```powershell
npm run android:open
```

This opens the generated `android/` project in Android Studio.

For a real phone on the same Wi-Fi:

```powershell
$env:CAPACITOR_SERVER_URL="http://YOUR_COMPUTER_LAN_IP:3000"; npm run cap:sync
```

Replace `YOUR_COMPUTER_LAN_IP` with your PC's LAN IP, for example `192.168.1.23`. Start Next.js with a network-accessible host:

```powershell
npx next dev -H 0.0.0.0
```

For production:

```powershell
$env:CAPACITOR_SERVER_URL="https://your-production-domain.com"; npm run cap:sync
```

This points the APK to the deployed FocusArx server. Use HTTPS for production because NextAuth cookies, camera behavior, and modern WebView security are more reliable over HTTPS.

## Android Studio Steps

1. Install Android Studio.
2. Open `E:\FocusArx\focusarx\android`.
3. Let Gradle sync finish.
4. Select an emulator or USB-connected Android device.
5. Click Run to install a debug APK.
6. When prompted on the device, allow camera permission.
7. Test login/signup, timer, AI focus camera, floating camera drag, dashboard, and session syncing.

## Debug APK

From Android Studio:

1. Open `Build`.
2. Choose `Build Bundle(s) / APK(s)`.
3. Choose `Build APK(s)`.
4. Android Studio outputs a debug APK under `android/app/build/outputs/apk/debug/`.

From terminal:

```powershell
cd E:\FocusArx\focusarx\android
.\gradlew assembleDebug
```

This builds `app-debug.apk`.

## Signed Release APK

Create a keystore:

```powershell
keytool -genkeypair -v -keystore focusarx-release.keystore -alias focusarx -keyalg RSA -keysize 2048 -validity 10000
```

This creates a private signing key. Keep it safe; losing it means you cannot update the same Android app listing later.

In Android Studio:

1. Open `Build`.
2. Choose `Generate Signed Bundle / APK`.
3. Select `APK`.
4. Choose `focusarx-release.keystore`.
5. Use alias `focusarx`.
6. Choose `release`.
7. Finish the wizard.

Terminal release build after configuring signing in Android Studio:

```powershell
cd E:\FocusArx\focusarx\android
.\gradlew assembleRelease
```

The release APK is written under `android/app/build/outputs/apk/release/`.

## Camera and MediaPipe Checklist

- Keep `android.permission.CAMERA` in `AndroidManifest.xml`.
- Use a real device for final camera testing; emulators often have limited camera behavior.
- Allow camera permission in Android settings if you denied it the first time.
- MediaPipe and TensorFlow model files are loaded from CDN/storage URLs, so the device needs internet access.
- If you want fully offline AI tracking later, copy MediaPipe WASM/model assets into `public/` and change the model URLs to local paths.

## NextAuth and Backend Checklist

- `AUTH_SECRET` must be set on the deployed server.
- `CAPACITOR_SERVER_URL` should match the public origin used by NextAuth.
- For production, configure NextAuth/Auth.js trusted host/origin environment variables according to your deployment.
- Prisma stays on the server; do not bundle database files into Android.

## Troubleshooting

White screen:

- Confirm `CAPACITOR_SERVER_URL` was set before `npm run cap:sync`.
- Confirm the Next.js server is reachable from the emulator/device.
- For emulator, use `http://10.0.2.2:3000`, not `localhost`.

Camera permission denied:

- Uninstall/reinstall the app or enable camera in Android app settings.
- Test on a physical device.
- Confirm the loaded URL is the Capacitor app URL or HTTPS production URL.

API calls fail:

- Check that the phone and computer are on the same network.
- Start Next with `npx next dev -H 0.0.0.0` for LAN testing.
- Make sure firewalls allow inbound traffic on port `3000`.

MediaPipe fails:

- Confirm the device has internet access.
- Check Android Studio Logcat for CDN/model download errors.
- Try disabling battery saver while testing focus tracking.

Timers pause unexpectedly:

- The native activity keeps the screen awake while FocusArx is open.
- Android may still throttle background WebViews if the app is minimized; foreground focus tracking should stay inside the open app.
