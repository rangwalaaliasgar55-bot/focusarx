### Context: what you're working on

FocusArx is a focus/productivity app: Pomodoro-style sessions with webcam-based attention tracking, gamification (XP, coins, badges, streaks, missions, a rank/"forge" system), an AI study coach, AI-generated roadmaps, and social/community features. It's a pnpm monorepo — `artifacts/focusarx` is the React 19 + Vite + Tailwind CSS 4 frontend (Framer Motion, Radix UI, shadcn/ui, TanStack Query, Wouter, React Three Fiber), `artifacts/api-server` is Express 5 + Drizzle ORM + Postgres. It already has real users and an existing design language — dark background, violet/teal/gold accent tokens, glow shadows, rank/rarity colors — defined in `artifacts/focusarx/src/index.css`. It also already has a lot of bespoke motion and effects work: a Three.js background, canvas-based particle and "orb" systems on the landing page, a cursor-glow effect, confetti and XP-burst celebrations, tilt cards, ambient sound. **Read all of this before changing anything.**

### What "full redesign, maximum effort" actually means here

This app doesn't need *more* visual effects layered on — it already has a lot of them, often several stacked on one screen (Three.js background + canvas particles + orb + cursor glow, for example). What it needs is **one coherent, disciplined design system and motion language, applied consistently everywhere**, with the existing effects consolidated and elevated rather than piled on. "Maximum effort" means craft and consistency at the level of a top-tier AI product — think Linear, Vercel, Arc, Raycast, Perplexity — not the sheer volume of extra widgets. Where an existing effect earns its place in telling the "AI-powered precision focus tool" story, refine and keep it. Where several effects are competing for attention on one screen, or costing frame rate on a mid-range phone, consolidate down to the one that actually earns it.

Because the product's core promise is AI-driven (AI coach, AI roadmap, webcam-based attention detection), the UI should read as AI-native — but avoid the generic version of that look: no default purple-to-blue gradient blobs everywhere, no stock robot/circuit iconography, no glass effect slapped on literally every card out of habit. Aim for a distinct point of view inside that visual language: living gradient meshes used sparingly as accents rather than wallpaper; subtle grain/depth instead of flat fills; confident, restrained spring-based motion rather than bouncy or linear tweens; generous negative space even on data-dense screens; monospace numerals anywhere focus is being measured (timer, streaks, stats) to reinforce a "precision instrument" feel; glass/blur reserved for places that genuinely communicate elevation or hierarchy, not decoration.

### Design system foundation — build and lock this in first, as its own phase

- **Refine, don't replace, the existing tokens** in `index.css`. The violet/teal/gold identity with rank/rarity colors is already on-brand — tighten contrast, remove near-duplicate values, and make sure both dark and light mode are fully considered, not just dark.
- **Typography:** pick one confident display face for headings and one for body/UI. Confirm whatever `--font-geist-sans` is meant to resolve to is actually loaded (via `@font-face`, self-hosted files, or Google Fonts) rather than silently falling back to `system-ui`. Define one real type scale (display / h1–h4 / body / caption) and use it everywhere.
- **Spacing & layout:** one spacing scale, one radius scale, one elevation/shadow scale, used consistently across all ~63 pages instead of ad hoc values per page.
- **Motion primitives:** define a small, shared set of Framer Motion variants — fade-up-in, staggered-children reveal, spring hover/press, a shared page transition — that every page reuses. Don't repeat bespoke one-off animation code (the current landing page alone is 900+ lines with hand-rolled canvas/orb/particle logic) 63 more times.
- **Motion rules:** spring-based easing by default (not linear, not overly bouncy); fast durations (~150–200ms) for micro-interactions, slower (~400–600ms) for entrances; every animation respects `prefers-reduced-motion`.
- **Component system:** one button system, one card system, one input system, one modal/toast system. Audit the existing 50+ components in `artifacts/focusarx/src/components` for near-duplicates before redesigning them piecemeal.
- Ship this phase as a small internal style-guide/demo route so the system can be reviewed on its own before it's rolled out everywhere else.

### Frontend completeness — "everything" means all of this, not just hero sections

This redesign is UI/frontend-only in scope (see rule 2), but within that scope it should be genuinely total. Treat every item below as in-scope design work, not optional polish:

- **Every interactive state, for every component** — default, hover, focus-visible, active/pressed, disabled, loading, error, success. A button or card that only looks good in its default state isn't done.
- **Every breakpoint** — phone (~375–428px), tablet (~768px), laptop (~1024–1440px), large desktop. Check real layouts at each; don't just shrink the desktop version and call it responsive.
- **Every form and input** — login/signup/settings/checkout all get validation states, inline error messages, visible focus rings, sensible autofill styling, and (where relevant) password-visibility toggles. Forms are UI too.
- **Loading, empty, and error states for every data-driven screen** — analytics, ai-insights, dashboard, leaderboard, social feeds, etc. These are real design surfaces, not a generic spinner bolted on afterward.
- **Iconography** — one consistent set (the app already uses `lucide-react`; keep using it rather than mixing in a second icon library for "new" pages).
- **Dark and light mode, both fully designed** — light mode isn't an afterthought to dark mode.
- **Cross-browser correctness** — Safari especially, where `backdrop-filter`/glass effects and some Framer Motion/Three.js behavior can render differently than Chrome.
- **The small stuff that's still frontend** — favicon, app/PWA icons, the `og:image`/social preview card, browser tab title and theme-color, and the `not-found` (404) page.

**Design Mode / Design Canvas isn't the right tool here** — that's built for prototyping a new frontend from scratch before a backend exists. This is a full, already-live app with real data behind it, so this is Agent Mode work on the existing code, not a Design Canvas mockup.
